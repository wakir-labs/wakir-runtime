# Hash-pinned wheel set for the wakir-provisioner image
# (``infra/spire/federation/provisioner/Containerfile``). Consumed by
# the Containerfile's ``pip install --require-hashes`` step.
#
# Why hash-pinned?
# ----------------
# Image layer digests pin the BUILD output bit-for-bit. Hash-pinned
# wheels pin the BUILD INPUT bit-for-bit. The image-pin (in
# ``infra/spire/federation/IMAGE_PINS.md`` §1, row
# ``ghcr.io/wakir-labs/wakir-provisioner``) gives runtime-side
# supply-chain provenance; this file gives build-side supply-chain
# provenance. Hash drift in either layer halts the rollout.
#
# Sprint-9 Tag-4 hygiene (Tag-4 follow-up, image v0.1.1)
# ------------------------------------------------------
# After Reza-PR #33 (Wirelang-Import-Disentanglement, PEP-562 lazy
# ``__getattr__`` on ``wirelang.federation``), the provisioner's
# transitive import chain through ``wirelang.federation.marker_stack_kv``
# no longer pulls in ``wirelang.identity`` at import time. Three of the
# four wheels the v0.1.0 image carried (``cryptography``, ``rfc8785``,
# ``jsonschema``) were carried purely to satisfy that transitive chain.
# After the disentanglement, the provisioner's actual runtime wheel
# need shrinks to ``nats-py`` only. This file reflects that shrink.
# The v0.1.0 image stays publishable for backward-compat; the v0.1.1
# image is the lean variant.
#
# Operator-Hand resolution recipe
# -------------------------------
# Wheel hashes resolved from the PyPI JSON API on the build host:
#
#   curl -fsS https://pypi.org/pypi/nats-py/2.14.0/json \
#     | jq -r '.urls[] | "--hash=sha256:" + .digests.sha256'
#
# Sandbox boundary: the claude-dev sandbox per
# ``feedback_sandbox_host_trennung.md`` may consult the PyPI JSON API
# read-only via WebFetch (trusted external source) for hash resolution
# of a single canonical artefact set; pip / install / network egress
# stay Operator-Hand on the build runner.
#
# Bump procedure (gated)
# ----------------------
# To upgrade the pinned ``nats-py`` wheel:
#   1. Bump the ``==`` version below.
#   2. Resolve the new wheel + sdist sha256 hashes from the PyPI JSON
#      API and substitute them below (one ``--hash=sha256:<64-hex>``
#      line per artifact).
#   3. Bump ``nats-py`` ONLY in lockstep with the top-level
#      ``requirements-nats.txt`` pin — the two files MUST agree
#      byte-precisely on the ``nats-py`` version (the bind-mounted
#      host runtime tests against the same version the provisioner
#      image carries).
#   4. Bump the image tag in ``Containerfile`` labels, in
#      ``IMAGE_PINS.md`` §1, and in the consuming Quadlet
#      ``quadlet/wakir-nats-kv-bucket-init.container``.

# nats-py — NATS-JetStream client. Same version pin as
# ``requirements-nats.txt`` (Sprint-4 Tag-2 First-Time-Live-Smoke
# baseline). License: Apache-2.0.
