# Hash-pinned wheel set for the wakir-provisioner image
# (``infra/spire/federation/provisioner/Containerfile``). Consumed by
# the Containerfile's ``pip install --require-hashes`` step.
#
# Why hash-pinned?
# ----------------
# Image layer digests pin the BUILD output bit-for-bit. Hash-pinned
# wheels pin the BUILD INPUT bit-for-bit. The image-pin (in
# ``infra/spire/federation/IMAGE_PINS.md`` §1, row
# ``ghcr.io/wakir-labs/wakir-provisioner``) gives runtime-side
# supply-chain provenance; this file gives build-side supply-chain
# provenance. Hash drift in either layer halts the rollout.
#
# Operator-Hand resolution recipe
# -------------------------------
# The hashes below carry the placeholder token
# ``HASH_PENDING_TOMAS_REVIEW`` because the claude-dev sandbox does
# not touch PyPI per ``feedback_sandbox_host_trennung.md``. The build
# host (the GitHub-Actions runner driving
# ``.github/workflows/build-wakir-provisioner.yml``, or an
# Operator-Hand build host) resolves each placeholder:
#
#   1. For each pinned package, fetch the canonical sha256 from
#      ``https://pypi.org/pypi/<pkg>/<version>/json`` (look at the
#      ``urls`` array entries; one entry per artifact, each carries
#      ``digests.sha256``). Include BOTH the wheel hash AND the sdist
#      hash so the build can resolve either depending on the runner's
#      platform.
#   2. Cross-validate with ``pip hash --algorithm sha256 <file>`` on a
#      locally-downloaded artifact.
#   3. Substitute the placeholder in this file with the resolved
#      hashes (one ``--hash=sha256:<64-hex>`` line per artifact).
#   4. Commit the resolved file alongside the image-build run. The
#      build job re-verifies the hashes during ``pip install``.
#
# Why placeholder-then-resolve (not pre-resolved)
# -----------------------------------------------
# The sandbox boundary (``feedback_sandbox_host_trennung.md``) forbids
# the claude-dev environment from reaching PyPI for any provenance
# operation. Placeholders preserve the sandbox-hermetic invariant while
# documenting the resolution recipe. A hermetic test
# (``provisioner/tests/test_requirements_hash_form.py``) enforces that
# every line either carries the placeholder token OR a canonical
# 64-hex sha256 — half-resolved state is an invariant breach.
#
# Bump procedure (gated)
# ----------------------
# To upgrade any of the four pinned wheels:
#   1. Bump the ``==`` version below.
#   2. Reset the ``--hash=`` lines to the placeholder token so the
#      sandbox-side hermetic test passes; the next build run resolves
#      the new hashes Operator-Hand.
#   3. If the bump changes wire-format / API semantics on the
#      Wirelang side, run a Cross-Review Zone-B paired-update with
#      Reza.
#   4. Bump ``nats-py`` ONLY in lockstep with the top-level
#      ``requirements-nats.txt`` pin — the two files MUST agree
#      byte-precisely on the ``nats-py`` version (the bind-mounted
#      host runtime tests against the same version the provisioner
#      image carries).

# nats-py — NATS-JetStream client. Same version pin as
# ``requirements-nats.txt`` (Sprint-4 Tag-2 First-Time-Live-Smoke
# baseline). License: Apache-2.0.
nats-py==2.14.0 \
    --hash=sha256:HASH_PENDING_TOMAS_REVIEW \
    --hash=sha256:HASH_PENDING_TOMAS_REVIEW

# cryptography — secp256k1 + Ed25519 primitives. Used transitively
# by ``wirelang.identity.key_derivation`` (Reza-side disentanglement
# Sprint-9 Tag-4 may flatten this path; the image carries the wheel
# regardless to keep the bind-mounted runtime importable end-to-end).
# Pin baseline matches the lower bound in ``pyproject.toml``
# (``cryptography>=42``); pinned to the latest 42.x line until a
# Cross-Review Zone-B bump approval lands. License: Apache-2.0 + BSD.
cryptography==42.0.8 \
    --hash=sha256:HASH_PENDING_TOMAS_REVIEW \
    --hash=sha256:HASH_PENDING_TOMAS_REVIEW

rfc8785==0.1.4 \
